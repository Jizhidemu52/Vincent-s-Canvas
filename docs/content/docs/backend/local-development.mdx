# 本地开发

业务功能需要 API 服务。默认试用部署关闭 OA 与独立账号登录：正式后端建立访客会话，单机演示后端使用共用创作身份。正式后端还支持以下独立账号模式；旧员工或试用数据不自动迁移。只启动 `web/` 不能调用生成或服务端素材接口。

## 独立账号与可选积分

正式 API 设置 `AUTH_ENABLED=true`、`OA_LOGIN_ENABLED=false`，可选 `ROLE_PORTALS_ENABLED=true` 显示账号入口；`CREDITS_ENABLED=false` 作为首次未保存策略的默认值。执行全部迁移（含 `030_credit_policy.sql`）及受控管理员初始化后，管理员从 `/admin/login` 登录，在“账号额度”创建个人账号；个人从 `/login` 登录，首次必须改密码。身份验证完成后才载入业务缓存，账号之间按用户分区；切换身份整页重新初始化，不读取旧共用缓存。

“账号额度 → 积分计费总开关”可以随时关闭或开启计费。仅超级管理员可修改，部门管理员只读；关闭保留余额和板块价格，新任务不扣分。已提交任务按提交时快照结算／退款，不被中途切换开关改价。每个新任务在服务端重新读取开关，已打开页面刷新后显示最新状态。

“编辑账号 → 当前可用积分”设置绝对余额；“本月临时加减”在余额上追加；“每月固定额度”控制下一自然月重置。板块费用在“板块 API 配置”编辑，0 表示免费，留空继承操作价与模型价；对话按每次成功模型调用计费，工具续答可能产生多次调用。演示服务不解锁共享管理员或模拟正式持久化。

## 统一对话模型

管理员从“API 配置 → 板块配置 → 对话改图”选择“统一对话模型”。`gpt-chat.modelConfigId` 同时控制独立对话改图与画布对话、文字生成和反推；设计师端不展示 LLM 模型名或选型控件。`canvas-chat` 保留自己的启用开关、积分和成本覆盖，模型跟随统一设置，不能独立覆盖。图片、视频模型仍沿用各自配置。

初始模型为现有 APIMart Claude Sonnet 5.5。正式服务执行 `031_default_chat_model.sql` 为未维护的初始配置写入默认绑定；后续管理员保存的选择不被初始化覆盖。服务端逐次解析统一模型，不使用请求里的旧模型选择。未配置、模型停用或服务不可用时停止调用，不自动回落其他模型；本机 Codex bridge 与管理员使用分析不在此设置范围内。

## 隔离本地 QA

从仓库根目录运行 `bun server/scripts/admin-credits-qa.ts --serve`；需要已有 `output/mark-admin-qa/runtime` 的 PGlite 运行库及完整前端构建。脚本仅监听 `127.0.0.1:5190`，在 `output/admin-credits-qa/run-*` 新建测试数据库与随机测试账号，不使用生产数据。启动日志提供本次目录及凭据文件位置；追加 `--resume <本次目录>` 可重开同一份数据库和测试素材，缓存替身不跨进程保存。

该环境复用正式认证、账号、积分策略、后台配置和画布文档路由，并挂载普通用户的项目、历史、团队、提示词、素材、设计效能与能力查询接口。素材通过本次运行目录内的 `media/` 适配器保存和读取真实字节，可检查上传／下载和账号权限；它不是 S3/MinIO，也不支持外部模型签名下载或对象删除流程。

以下边界不能被本地页面可操作或 SQL 测试通过替代：

- 数据库是单连接 PGlite，缓存为内存测试替身；不验证 PostgreSQL 多连接行锁、真实 Redis、目标部署备份恢复或公司 OA。
- 脚本进程的全局 `fetch` 一律拒绝请求；不挂载聊天／生成提交接口，不启动生成 Worker，后台任务只允许读取。真实模型、网页采集和未纳入接口均不可用于此环境验收；保存 Provider 配置不等于已联通供应商。
- 本地素材适配器不验证正式 S3 签名地址、对象删除、存储权限与跨设备原图访问。进程异常退出后的对话冻结恢复、真实供应商计费和生产故障恢复仍须单独验收，见 [待验收](/docs/progress/pending-test)。

## 网页参考图采集

`POST /api/reference-import/scan` 接收 `{ url }`，`POST /api/reference-import/image` 仅接收扫描返回的 `{ scanId, imageId }`，均要求现有会话、同源请求和匹配的 `X-Canvas-Owner-Id`；正式服务受 `assets` 模块开关保护。预览不创建素材，确认入库复用既有素材上传接口。

抓取在 PATH 中的原生 Node 子进程进行，检查全部 DNS 结果并固定公网地址，每次重定向重新校验，保留 TLS 证书校验；不继承代理、Cookie、Authorization 或网页 Referer。仅支持 HTTP／HTTPS 标准端口，HTML 上限 2 MiB，单图 10 MiB，解压前后均检查大小；单次传输限时，临时记录按员工隔离、5 分钟过期，全局缓存 64 MiB、并发 4，另有扫描频率和条数上限。此入口不支持登录页、浏览器脚本渲染或模型代理配置，不开放任意图片 URL 下载接口。

## 模型 HTTPS 运行要求

API、Worker 和本机演示服务仍运行于 Bun；对话及已接入的图片 HTTPS 提交另外使用 PATH 中的原生 `node`。要求 Node.js 22.x（22.21.0 起）、24.x（24.5.0 起）或 25 及以上版本；不支持 Node.js 23.x 和 24.0–24.4。服务镜像安装 Node.js 和 CA 证书后会检查版本，不满足要求则构建失败，避免旧版静默忽略代理配置；非 Docker 启动前请用 `node --version` 确认版本。密钥只通过子进程标准输入传递，不写入命令参数或前端。

该传输每次尝试使用独立连接，显式继承服务进程的 `HTTP_PROXY` / `HTTPS_PROXY`、对应小写变量以及 `NO_PROXY` / `no_proxy`；同名大小写变量同时设置时，小写优先。HTTPS 模型地址使用 `HTTPS_PROXY` / `https_proxy`，代理 URL 支持 `http://` 和 `https://`。未配置适用代理或地址匹配 `NO_PROXY` 时直连；显式代理连接失败时直接报错，绝不自动回退直连，也不跟随提交重定向。

代理转发 HTTPS 模型请求时，`CONNECT` 只建立到目标地址的隧道，不携带模型业务 API Key、`Authorization` 或请求体；如代理 URL 自带凭据，只用于代理认证。目标 TLS 证书和身份验证通过后才发送模型业务 POST。只有明确的初始 TLS 证书错误或 `ECONNRESET`，且已确认模型业务HTTP请求尚未发送时，才允许重试一次。模型业务 HTTP 已发出、阶段未知、超时、响应解析或下载失败均不重放生成提交；不要关闭证书校验。

非视频任务执行报错后不再自动重试整个任务；若服务重启时发现已在执行但结果不明的任务，则暂停并保留待核查状态，普通恢复按钮不能直接重新提交。已发出请求但遇网络故障时，上游仍可能已经执行，请先核查结果，避免重复计费。视频仍沿用原上游任务 ID 恢复查询。

## 生图耗时定位

正式 Worker 与单机演示的 OpenToken 图片调用输出 `event=generation_timing` 的 JSON 日志，可按 `taskId` 关联同一任务。日志只包含任务 ID、模型配置 ID、尝试次数、运行入口、阶段、结果和毫秒耗时，不包含提示词、图片内容、Provider URL、凭据或错误正文；日志写入失败不会中断生成。

`provider_request` 是发送请求至收到响应头，`provider_response` 是读取并解析响应体，`result_download` 是上游返回图片 URL 后取回图片（内联图片不产生该下载阶段），`result_store` 是保存结果，正式 Worker 的 `task_finalize` 是结算及完成状态落库。`prepare` 记录请求准备或参考图读取。每段有 `phase=start/end`，未结束的 `start` 表示当前仍在等待该边界；`phase=complete` 记录本轮执行结果。`durationMs` 是单段时长，`elapsedMs` 是本轮开始后的累计时长；正式 Worker 的 `provider_execution` 包含其内部阶段，不能与子阶段相加。工作流及非 OpenAI 协议目前只有整体执行/保存计时，不承诺同样细分。

这些时间不能直接区分供应商内部排队与模型推理；即使响应头提前返回，主要等待也可能落在读取响应体。后端队列耗时仍查任务的 `queuedAt/startedAt`。图片、批量和媒体任务结束后的会话刷新在后台继续，不阻塞结果交付，也不跳过员工身份与账号状态更新。

## 单机演示数据保存

`bun run dev:demo` 自动将上传原文件、素材名称/标签/备注和任务记录保存到 `server/.data/local-demo.sqlite`；默认路径以源码位置为基准，不随当前工作目录改变。`DEMO_STATE_PATH` 可覆盖路径，建议使用持久磁盘的绝对路径。该目录不提交 Git，请确保可写并定期备份。

重启保留这些记录；中断中的任务暂停，不自动重复生成。磁盘满或不可写时返回保存失败，不伪称完成。试用会话、后台临时 Provider 配置和演示余额仍在内存；企业 OA 员工映射、会话与云端画布则持久化。旧共用和其他员工数据不自动迁移或公开。长期凭据写服务端配置，正式后端使用 PostgreSQL/Redis/S3。

备份时先停止演示服务，再复制整个 `server/.data` 目录（自定义路径则备份其数据库与日志文件）；不要在运行中只复制 `.sqlite` 文件。企业画布文档与原图按员工同步服务器，本地保留 localforage / IndexedDB 缓存；确认已同步后可由本人恢复。试用画布、独立聊天和创意草稿仍是浏览器数据，跨浏览器需另存/导出，服务器备份不替代本地内容备份。`DEMO_RECOVERY_FILE` 只用于数据库首次初始化，不会倒灌覆盖已有数据。

画布库使用 `GET /api/canvas-documents` 读取员工范围内的摘要与删除墓碑（`summary` 含标题、节点/连线数量及封面，不含完整图和历史）；`GET /api/canvas-documents/:id` 按需返回完整 `document` 和 `revision`，缺失项目返回版本 0 的空墓碑。写入仍使用原有 `PUT` 与 `baseRevision` 条件更新。客户端历史采用 `canvas-history-delta-v1` 无损差量表示，当前图保留完整，服务端对历史差量中的素材继续执行归属校验；没有新增数据表。演示 SQLite 与正式 PostgreSQL 提供相同读写契约，正式环境仍需按待验收清单实测。

WSL 的代理回归使用原生 Node HTTPS/CONNECT 测试服务并等待明确就绪事件，验证隧道不泄漏业务凭据、TLS 通过后才发送 POST。准备阶段与网络提交超时分开，避免冷启动或磁盘挂载停顿污染后续测试；这不代表 WSL 主机 I/O 或真实模型出口已经稳定。

## 分开启动前端

