# 画布数据结构

类型以 `web/src/stores/canvas/use-canvas-store.ts` 和 `web/src/types/canvas.ts` 为准。本文只描述当前实现，不维护一份容易过时的完整类型副本。

## 画布文档

`CanvasProject` 保存项目 ID、名称、时间、节点、连线、画布内聊天、当前会话、背景、图片信息显示设置与视口。历史保存最多 50 步撤销/重做快照；冲突副本带有来源与冲突信息。

节点保存类型、名称、世界坐标、尺寸及元数据。图片/视频元数据引用原文件，文本节点保存文字，配置节点保存模型和参数。连线引用两端节点 ID，不保存渲染坐标。画布内会话与独立 `/chat` 页面的本地聊天不是同一个存储。

## 本地缓存

- 项目存储由 `web/src/lib/canvas/canvas-project-storage.ts` 管理：一个有序索引，加每个项目独立的 JSON 文档；修改一个项目不会重写所有项目。
- 非 OA 命名空间为 `wireless-canvas:canvas_store`；OA 使用追加员工 ID 的独立命名空间，身份确认后才初始化。
- 索引键追加 `:project-documents:v1`，项目文档键由索引键和项目 ID 共同构成。
- 图片、视频等 Blob 由 `image-storage.ts`、`file-storage.ts` 管理，元数据中的 `storageKey` 用于本地恢复。`blob:` URL 只供当前浏览器展示，不是可跨设备保存的文件地址。
- 写入采用事务与三方合并。失败保留待写内容；不能自动合并的冲突另存副本，不覆盖原文档。

旧共用/旧格式画布不自动迁入员工账号。需要保留时从原环境导出，再以目标身份导入；清理源码不应删除这些用户数据。

## OA 云同步

`web/src/services/canvas-cloud-persistence.ts` 将本地缓存与 `/api/canvas-documents` 对接：

1. 先保留本地修改，上传尚未在服务端保存的原始媒体。
2. 提交完整画布文档及基准版本，服务端按当前员工校验归属。
3. 成功后标记已同步；断网或失败保留待同步内容并重试。
4. 版本冲突保留完整副本；删除写入墓碑，旧设备不能复活原 ID。

同步包含节点、连线、媒体引用、编辑结果、画布聊天、视口与有限撤销/重做历史，不是实时多人协作或无限历史。

Windows OA 服务将文档、员工身份与媒体写入 SQLite；正式服务使用 PostgreSQL `canvas_documents` 和 S3/MinIO。非 OA/standalone 仍使用本地画布。

## 媒体与导出

原始媒体字节与文档分开保存。云端引用必须属于当前员工，未上传的本地文件不能仅凭 `blob:` 地址恢复；读取时优先使用可用的本地文件，再按权限下载服务端原文件。

画布 ZIP 包含可恢复文档及引用媒体。缺少原文件时应明确失败，不把不完整的导出报告为成功。图片集 PDF/ZIP 只交付成果，不包含完整画布结构。

OA 模式下，未加载的旧/其他员工本地媒体不能作为“未引用”而清理。服务端权限和删除校验与本地缓存清理各自负责，不可通过清空浏览器数据替代恢复流程。
