# 数据库结构与迁移

正式 API 和 Worker 使用 `server/src/migrations/` 中的 PostgreSQL 迁移，完整表结构以这些 SQL 为准。`server/src/demo-server.ts` 使用本机 SQLite 保存素材、任务，以及企业 OA 模式下的员工身份和云端画布。`OA_LOGIN_ENABLED=true` 复用 OA 员工身份，`false` 用于本机试用；两种模式关闭内部积分，不删除、合并或公开旧账号数据。

| 存储 | 负责内容 |
| --- | --- |
| PostgreSQL | 用户、部门、项目、员工画布文档、公司设计灵感库及使用收据、任务、使用统计事件与分析预览、额度账本、历史、审计、Provider 配置与素材元数据 |
| Redis | 会话、任务队列、限流和并发控制 |
| S3 / MinIO | 上传文件及生成结果的文件内容、灵感库独立原图快照及复用后的私有原件 |
| 浏览器 IndexedDB | 企业画布的员工缓存、待同步改动和媒体；试用画布本地持久化；独立聊天与创意草稿仍为本地员工分区 |
| 单机演示 SQLite | 演示服务的素材原文件、元数据、任务、OA 员工身份／会话、整张画布文档及灵感库快照与使用收据，不替代上述正式存储 |

## 单机演示数据

默认文件是 `server/.data/local-demo.sqlite`，可用服务端 `DEMO_STATE_PATH` 指定持久磁盘路径。数据库使用 WAL 日志和 `synchronous=FULL`，上传/编辑在事务提交后返回成功，生成结果原文件与成功任务在同一事务保存。

| 表 | 字段与约束 |
| --- | --- |
| `demo_assets` | `id` 主键、`fields_json` 素材字段、`bytes` 原始 BLOB；空 BLOB 仅用于尚未上传的申请占位 |
| `demo_tasks` | `id` 主键、唯一 `request_id`、`fields_json` 完整任务状态及上游任务 ID |
| `demo_state_metadata` | `key` 主键、`value`；`initialized` 防止旧恢复文件重复覆盖新数据 |
| `demo_oa_users` | `id` 内部用户主键、唯一 `subject` 对应 OA `userid`、`display_name` 对应姓名；同名不合并，Token 更新不改变内部 ID |
| `demo_oa_sessions` | `token_hash` 平台会话 SHA-256 主键、`user_id`、`expires_at` 毫秒时间；有效期两小时，不保存 OA Token |
| `demo_canvas_documents` | `(owner_user_id,external_id)` 联合主键、`revision` 正整数、`deleted`、`document_json`、`updated_at`；额外保存标题、文档时间、节点数、连线数和封面，列表不解码整张画布 |
| `demo_asset_projects` | 按员工保存项目 UUID、外部画布标识、名称和更新时间；项目同步与素材批量移动使用同一持久身份 |
| `demo_library_publications` | `id` 主键、`author_id`、`department_id`、`request_id`、`status`、`created_at`、`fields_json`；`(author_id,request_id)` 唯一，JSON 保存显式发布内容与图片快照元数据 |
| `demo_library_media` | `object_key` 主键、`mime_type`、`bytes` 原始 BLOB；共享原图独立于作者的 `demo_assets` |
| `demo_library_deliveries` | `operation_key` 主键、`fields_json`；保存已签发的下载与私有素材复制操作，不等于已收到成功收据 |
| `demo_library_receipts` | `id` 主键、唯一 `operation_key`、`entry_id`、`image_id`、`action`、`actor_id`、`created_at`、`fields_json`；按作品、操作、图片、员工及时间建立统计和活动索引 |

启动时仅将遗留 `processing` 任务改为 `paused` 并记录 `LOCAL_PROCESS_INTERRUPTED`，不自动重新生成或退款；视频可沿用已有上游任务 ID 查询。旧演示账号登录会话、账号余额、后台临时配置仍在内存中；OA 身份和会话则持久化，不能把这里的退款标记当作正式持久账本。现有 `DEMO_RECOVERY_FILE` 仅在新数据库首次初始化时导入；坏数据库或写入失败会报错，不会自动删除并重建为空库。

## 图片模型展示编号

`024_model_public_numbers.sql` 为 `model_configs` 新增 `public_number integer` 唯一正整数，以及 `model_public_number_seq` 和写入触发器。现有图片模型按 `created_at,id` 初始化编号；新图片模型从序列分配，停用、改名、重排或修改能力不改变已分配编号。真实 `name`、`model_id`、Provider 配置仍用于管理员维护和服务端调用。

设计师出图列表保留已知 APIMart 平台图片模型及四个 OpenToken 型号，`name` 与 `publicName` 显示明确的模型名称，保留 `publicDescription`；APIMart 使用 `aplmart-` 展示前缀，两个渠道不会因上游型号相同而合并。设计师响应中的 `modelId` 仍为配置 UUID，用于请求和可恢复导出；APIMart 在所有创作角色下均使用独立配置 UUID，真实上游型号只在管理接口返回。`modelIdentityHidden` 表示配置身份仍受保护，不表示展示名称匿名。原编号保留给其他图片配置及历史。公开接口不返回 Provider 配置或密钥；聊天、视频、音频保持各自能力和参数身份。正式服务升级前须执行相关迁移。单机演示服务在启动时按完整真实图片目录分配编号（包含未启用项，不包含模拟占位模型），之后在进程内保持编号。

## 热门出图模型与排序

`029_model_presentation_settings.sql` 新增单例表 `model_presentation_settings`，`singleton=true` 为主键，`featured_model_ids uuid[]` 保存至多 5 个有序的模型配置 UUID，另存 `updated_by` 和 `updated_at`。迁移不插入默认行：没有记录时按预设顺序选取已启用的 APIMart 平台出图模型，默认依次为 Flare、Sunburst、Nano2.1、MJ Blend、GPT2。已经保存的空数组明确表示“不展示任何热门模型”，不会再次填回默认项。保存后排序在刷新、服务重启和普通平台配置保存后保持；停用、移除或变更为不合格的模型不会被其他模型自动补位。

只有固定 `MARK_IMAGE_PROVIDER_ID`、`apimart` 协议、共享目录中已知型号，且具有 `generate`、不混有 `chat`／`video`／`audio` 能力的模型可进入候选。默认停用的 Grok2 可在启用后选入；Nano2 与 Nano2.1 是独立候选，GPT6 与 HappyHorse 不属于出图热门。后台候选列表保留停用项以说明原因，但不能保存停用模型或已停用平台。凭据是否存在只作为状态提示，不随排序接口读取或修改密钥。

超级管理员使用 `GET /api/admin/model-configuration/featured-models` 读取 `{models,featuredModelIds,maxFeatured}`，通过同路径 `PUT` 一次提交 `{modelConfigIds:[配置UUID...]}`。数组顺序就是展示顺序；重复、超过 5 项或非 UUID 返回 `400 VALIDATION_ERROR`，未知、非目标渠道或停用项返回 `400 INVALID_FEATURED_MODEL`。未认证返回 401，设计师和部门管理员返回 403。保存采用事务、共享模型／平台行锁和与平台配置共用的事务级锁，并在同一事务写入审计；多位管理员同时保存时，每次完整替换整个列表，最后提交的配置生效，不会拼接出混合顺序。

`GET /api/models` 和管理员模型列表投影安全字段 `isFeatured:boolean` 与 `displayOrder:number`；热门按 0 开始排序，非热门从 1000 起排在后面。公共接口只发布有效的热门状态，不泄露上述表、Provider 身份或凭据。其他渠道和未入选模型仍可在完整列表中使用，排序不改变模型 UUID、上游调用身份、工具绑定或价格。

本机试用仍拒绝 `/api/admin/**`，不新增试用管理员或后台写入口。其公共列表复用同一套默认热门算法，SQLite 不保存正式热门后台配置。正式部署需先运行正常 PostgreSQL 迁移；本地展示与路由测试不能替代目标数据库升级和真实管理员会话验收。

## 正式模块独立配置

`shared/feature-catalog.ts` 是正式功能目录：27 个 AI 板块与 17 个入口、本地工具或服务模块，包含 MJ 多图融合、正式图案定位、花型循环和系列配方。`026_formal_module_configuration.sql` 与 `027_midjourney_blend_module.sql` 扩展 `tool_api_configurations.tool_key` 和 `module_flags.module_key` 的检查约束，补齐目录记录，`ON CONFLICT DO NOTHING` 保留现有开关和绑定；027 仅纠正固定 APIMart 平台 Blend 的生成能力。应用新后端前须运行正常迁移流程；本地测试不会代替目标 PostgreSQL 环境验收。

| 字段 | 类型与语义 |
| --- | --- |
| `tool_api_configurations.model_config_id` | 可空 UUID；绑定时服务端权威选择该模型，空值允许用户选择已启用且能力匹配的模型 |
| `enabled` | 当前板块模型调用开关；`false` 拒绝调用，不能回退其他模型 |
| `credit_cost_override` | 可空非负整数；本板块每次输出的总积分价覆盖，0 是有效覆盖，NULL 沿用操作价加模型价 |
| `rmb_cost_override` | 可空 `numeric(12,4)`；本板块每次输出的总成本覆盖，0 是有效覆盖，NULL 沿用操作价加模型价 |
| `configuration_version` | 正整数，每次保存独立配置递增，不修改共享模型或全局操作价格 |
| `tasks.tool_key` / `batch_tasks.tool_key` | 可空文本外键，保存正式来源板块；历史任务保留原数据 |

管理员工具列表始终返回全部 27 项，公开模型接口同样保留禁用和未绑定项，但不公开 Provider 凭据。显式绑定的启用模型不会被默认精选列表过滤；已禁用模型或 Provider、工作流不能执行。任务、批量任务、视频预检及聊天入口先校验来源与操作匹配、自身和父模块开关，再校验绑定。客户端携带旧模型时返回 `TOOL_MODEL_CHANGED`，要求刷新模型参数，不静默换模型。MJ 多图融合仅可绑定、执行 Blend；画布生图仍可选择其余生成模型。未提供工具配置的旧调用只规范化已知来源名；显式未知键拒绝。

`credit_reservations.price_snapshot` 记录 `toolKey`、`configurationVersion`、两项可空覆盖价与最终总价，批量任务在本次提交中共用同一份单项快照。源板块已知时提示词价格估算应用相同覆盖规则。此变更不重新启用部署已关闭的积分；独立对话与画布聊天分别配置且仍不新增聊天计费。`module_flags` 的总入口关闭也阻止子模块；本地工具没有服务端 AI 计费接口。

## 企业 OA 身份与会话

`022_oa_login.sql` 允许 `external_identities.provider='oa'`，`subject` 保存上游已校验的 `userid`；沿用 `(provider,subject)` 和 `(user_id,provider)` 唯一约束。`037_wecom_session_provider.sql` 将 `sessions.auth_provider` 扩展为 `local`、`oa` 或 `wecom`，默认仍为 `local`。OA 模式的普通创作拒绝非 OA 会话及管理员维护身份，生产管理员接口另保留独立密码认证与角色校验。正式服务启动前须应用相关迁移；当前局域网 SQLite 服务不运行 PostgreSQL 迁移。

非 OA 模式下，新企业微信扫码在服务端完成身份交换、既有账号映射和绑定校验后写入 `wecom` 会话并直接进入主页。仅当前仍为非访客设计师的有效 `wecom` 会话，其返回的 `mustChangePassword` 为 `false`；账号的本地 `password_hash` 和 `must_change_password` 不变，本地密码登录仍执行首次改密要求。旧 `local` 会话不会根据绑定记录重新归类，须重新扫码才能使用新会话规则；停用、软删除、撤销、过期和管理员角色提升仍会使企业微信会话失效。

OA 登录请求向固定 HTTPS 用户信息接口发送 Bearer Token，仅使用返回的 `userid`、`name` 建立普通账号；不接受客户端声明的归属或角色。不存储上游 Token，旧记录不按姓名或首次登录自动转移给员工。

## 员工画布文档

企业模式使用以下表与协议保存完整画布及原图引用；试用模式保持浏览器本地画布。只有已验证的当前员工能读取本人云端文档，独立聊天与创意草稿不在整张画布云同步范围。

`023_canvas_documents.sql` 新增正式 PostgreSQL 表 `canvas_documents`：`owner_user_id uuid` 引用 `users(id)`，与 `external_id text` 组成联合主键；`revision bigint` 是安全整数范围内的正版本号，`deleted boolean`、`document jsonb` 与 `updated_at timestamptz` 记录完整内容或删除墓碑，并按员工与更新时间建立索引。约束要求未删除记录包含 JSON 对象，墓碑的文档为 `NULL`。单机演示在上述同一 SQLite 文件中使用 `demo_canvas_documents`，以 `document_json` 保存对应 JSON。

OA 员工模式的前端同步整张画布：节点位置与尺寸、连线、编辑内容、参考媒体、画布内聊天、最多 50 步撤销／重做历史和视口。文件沿用素材存储：正式环境为 S3／MinIO，演示环境为 `demo_assets.bytes`；同步上传保留文件原字节，不缩放或再次编码，文档只保存可访问的服务端素材引用，不持久化浏览器 `blob:`、媒体 data URL 或本地 `storageKey`。文档请求上限为 20 MiB。

`GET /api/canvas-documents` 只列当前员工的文档和墓碑；`?summary=1` 仅返回摘要，打开时通过 `GET /api/canvas-documents/:id` 获取完整内容。`PUT /api/canvas-documents/:id` 使用 `baseRevision` 比较并交换版本，初次写入从 0 开始，`document:null` 表示删除；成功仅返回 `{document:{id,revision,deleted,updatedAt}}`，不重复返回整张画布。所有接口要求 `X-Canvas-Owner-Id` 严格等于当前会话员工，并在保存时检查引用素材权限。SQLite 使用 `IMMEDIATE` 事务执行原子版本比较；冲突返回 409 和当前完整版本，前端保留冲突副本。真实删除墓碑不得以原 ID 复活，即使版本匹配；需要保留旧设备的改动时创建新 ID 的副本。

`034_canvas_document_summaries.sql` 新增 `title`、`document_created_at`、`document_updated_at`、`node_count`、`connection_count`、`cover_url`。迁移一次性从现有 JSON 派生；之后保存正文与摘要在同一次原子写入完成，列表不再遍历节点。删除墓碑同步清空摘要。SQLite 在启动时以事务完成相同的派生字段初始化。

本地提交先于云端提交；断网或同步失败保留缓存和待同步改动，恢复后重试并显示同步状态。旧匿名／共用本地画布不自动迁入员工账号，须由用户导出后导入。此机制不是实时协作或无限历史；非 OA／standalone 模式仍使用本地画布。新迁移在正式 PostgreSQL、S3／MinIO 联动及真实 OA 员工入口尚需目标部署环境验证。

## 公司设计灵感库

`025_design_library.sql` 新增以下四张正式 PostgreSQL 表。仅 `OA_LOGIN_ENABLED=true` 的已认证员工可以发布和使用公司分享，试用模式明确拒绝；真实作者、操作员工及部门来自服务端身份，不接受客户端声明。正式维护入口另用严格管理员认证，部门管理员仅管理所属部门的非公开分享及统计；单机演示不提供真实管理员登录。

| 表 | 字段与约束 |
| --- | --- |
| `design_library_publications` | `id` 主键、`author_id` 与作者／部门名称快照、`title`、`thought`、`prompt`、`tags`、`status`、`request_id`、`payload_hash`、下架原因／操作人及时间；`(author_id,request_id)` 唯一，状态限 `published`／`withdrawn`／`taken_down`，按公开状态、作者和部门建立时间索引 |
| `design_library_images` | `id` 主键、`entry_id`、`position`、唯一 `object_key`、文件名、MIME、原始字节数与尺寸；作品内位置唯一，支持 PNG／JPEG／WebP／GIF，单图不超过 20 MiB；不关联作者私有源素材外键 |
| `design_library_deliveries` | `operation_key` 主键、操作员工、作品／图片、`download`／`reuse`、`request_id`、`asset_id` 与时间；复用必须关联接收人的新私有素材，下载不关联私有素材 |
| `design_library_receipts` | `id` 主键、唯一 `receipt_key`、作品／图片、操作、员工 ID／姓名／部门名称、请求标识与时间；操作限浏览、下载、画布复用和提示词复制，图片外键绑定所属作品；提供统计和下载／复用活动分页索引 |

发布时只快照员工显式选择的内容和本人已保存的有效图片，不修改源素材权限，也不自动公开源素材元数据、私人画布或聊天。每次最多 12 张图片、总量不超过 100 MiB；校验真实图片格式后按原字节复制，不重编码。S3／MinIO 中的共享对象独立于原私有文件，复用再创建接收人拥有的私有 `assets` 与独立原件，并保留 `metadata.designLibrarySource` 来源归因。列表在数据库分页，不加载原图字节；SQLite 列表将设计思路与提示词留空作为摘要，详情返回完整显式发布内容。

发布按员工与 `requestId` 幂等，相同标识更换内容返回冲突；复制、下载签发及成功收据分别持久化。统计排除作者自己的操作，作品浏览只计详情打开，不把列表预取或图片请求算作浏览；逐图浏览另计。跨图片汇总人数按员工去重，下载／复用活动只包含姓名、部门、图片与时间，不保存接收人的私人画布 ID 或内容。下载计数是浏览器交付流程的成功收据，不证明外部落盘或实际采用；复制到画布需原件复制和本地画布保存成功后才提交收据。

SQLite 适配器在同一事务保存快照、分享、收据及接收人的 `demo_assets.bytes`，提交后才更新内存素材；外部读取不观察未提交状态。作者撤回或管理员下架后阻止新的共享读取、下载和复用，允许已签发操作完成收据；已有私有副本及下载文件不能收回，原作者仍可查看自己的分享和统计。正式迁移、对象存储权限与联合备份恢复仍须在目标 PostgreSQL／S3 环境验收。

## 任务执行与恢复字段

`038_task_progress_indexes.sql` 仅增加同模型活跃任务索引与同模型、同操作近期成功耗时索引，不新增表或字段、不改任务状态或调度。`GET /api/tasks/:id/progress` 先验证当前员工拥有任务，再只读查询真实 Redis 队列及近期成功样本；返回当前任务的名次和汇总耗时参考，不返回其他员工的任务编号或内容。候选上限为 1000，最近 7 天最多取 30 个同类单次成功样本，至少 3 个样本才估算；超过上限、信息不足或在途状态不确定时不猜测。正式部署前按现有事务迁移入口应用 `038` 及所有缺失的前置迁移；本次未在公司服务器执行。

`036_task_scheduling.sql` 新增 `available_at`（下一次可领取时间）、`execution_token`（本轮执行权）、`model_slot_token`／`model_slot_expires_at`（模型占位）和 `poll_deadline_at`（原视频查询截止时间），并建立等待／轮询／模型占位索引。Redis 就绪队列与延迟队列分开，未到期任务不会被提前弹出；模型并发使用有序集合租约与心跳，PostgreSQL 保留权威占位，Redis 丢失后可重建。

视频提交取得上游 ID 后，释放本地执行名额并在到期后单次查询，仍保留模型的在途占位；不会因释放本地 Worker 而突破模型并发限制。恢复只查询原 ID。已提交但结果不确定的任务保留占位和待核查状态，不自动重新提交；这可能有意阻塞后续同模型任务，须先核实原任务。

`018_task_execution_lease.sql` 为 `tasks` 新增 `lease_expires_at timestamptz`，并建立仅覆盖 `processing` 任务的租约索引。Worker 领取任务时写入租约；完成、失败或回队时清除。启动恢复只将租约缺失或已过期的执行中任务回队，避免立即抢占仍有效的执行。

`020_video_upstream_identity.sql` 为 `tasks` 新增以下可空字段：

| 字段 | 类型 | 用途 |
| --- | --- | --- |
| `upstream_task_id` | `text` | 保存视频服务商返回的原任务 ID，恢复时查询原任务 |
| `upstream_submission_started_at` | `timestamptz` | 标记已开始提交；无返回 ID 时保留提交不确定状态，防止自动重复生成 |

恢复查询不等于重新生成。已开始提交的视频发生不确定网络错误时保留原任务和预留额度，暂停后核实上游状态；只有明确失败或完成才能按对应流程结算。

## 账号删除与会话快路径

`032_users_deleted_at.sql` 新增 `users.deleted_at timestamptz`。密码、企业微信、OA 身份及会话读取均拒绝已软删除账号；已有被删的外部身份不因再次登录而自动创建替代账号。积分周期按北京时间月份计算，当前周期会话直接读取余额；只有确实跨周期的账号才进入刷新事务。

## 素材与列表索引

`033_performance_indexes.sql` 增加素材任务关联、预留额度用户／状态、批次用户时间、公司素材和个人／管理任务与历史游标索引。`035_asset_thumbnails.sql` 为素材增加 `thumbnail_256_key`、`thumbnail_1024_key`，以及全库／员工／部门／项目的 `(created_at DESC,id DESC)` 未删除素材索引。缩略图是派生 WebP 对象，原文件和原图下载不变。

列表默认每页 60 条、最多 200 条，按时间与 ID 稳定排序；游标保留 PostgreSQL 微秒精度，避免同一毫秒内跳过记录。任务恢复按已知 ID 或请求 ID 精确查询，不依赖最新一页。索引迁移使用项目现有事务迁移流程，不使用 `CONCURRENTLY`；应在维护窗口运行并先备份。本次代码更新不等于目标服务器已经执行这些迁移。

## 访客身份约束

`019_optional_access.sql` 为 `users` 新增 `is_guest boolean NOT NULL DEFAULT false`。数据库约束 `guest_is_unprivileged` 要求访客只能是 `designer`，不得有密码散列或首次改密要求。

完整后端仅在 `OA_LOGIN_ENABLED=false` 且 `AUTH_ENABLED=false` 的试用模式为浏览器分配访客身份。开启 OA 或独立密码登录后，不接受访客会话；访客不能通过密码登录或企业微信绑定绕过限制。演示服务的固定试用身份不能用于验证这种隔离。

## 积分计费策略

`030_credit_policy.sql` 新增单行 `credit_policy`：`singleton` 主键限定为 true，`credits_enabled` 保存开关，`updated_by` 引用操作者，`updated_at` 记录保存时间。未保存时沿用部署 `CREDITS_ENABLED`（默认 false）；保存后数据库值优先，重启不丢失。只有启用独立身份认证才能开启计费，修改策略和审计在同一事务。

个人绝对余额设置与加减分沿用 `credit_ledger`，metadata 记录 `mode`、`requestedValue`、`balanceBefore` 和当月周期；用户锁与请求编号锁保证幂等边界，余额、流水和审计同时提交。设置当月可用余额不改变每月固定额度，跨月仍按原规则重置。

文字模型调用沿用 `credit_reservations`：每次模型请求独立冻结，成功结算，明确失败、空回复和不完整流返还；聊天请求编号按用户命名空间隔离。异常进程退出遗留的冻结暂无自动恢复机制，正式上线前需核验运维处理，不将隔离 SQL 测试视为崩溃恢复验收。

## 员工使用统计与分析

`028_usage_analytics.sql` 新增以下四表；仅正式 OA 企业模式开放采集及人员分析，单机试用不提供该能力。

| 表 | 关键字段与约束 |
| --- | --- |
| `usage_collection_metadata` | 单行 `singleton` 与 `started_at`，标记实际采集起点，不冒称旧点击已经存在 |
| `usage_events` | `id`、`event_id`、`user_id`、`board_key`、`action`、`control_key`、白名单 `parameters`、`occurred_at`、`received_at`；`(user_id,event_id)` 唯一，重传不重复计数；员工／板块时间索引支持查询 |
| `usage_chat_requests` | 请求 ID、员工、模型配置 UUID、来源板块、完整脱敏的本次用户 `prompt`、`prompt_redacted`、状态和时间；不复制 system、历史消息、工具输出或媒体内容 |
| `usage_analysis_previews` | 发起管理员、冻结内容与 SHA-256、筛选、是否带提示词片段／片段数、有效期、消费时间、明确选择的模型 UUID、执行状态与结果；一次性原子领取防止重复调用 |

生成次数和原始提示词直接查询既有 `tasks`，不复制任务、不重写历史；恢复或改变执行次数不会增加请求数。文字从启用后开始记录，客户端事件的员工身份取自服务端会话，拒绝自报其他员工 ID。读取与导出会再次隐藏凭据样式文本，模型分析只取得预览内的匿名聚合和显式选择的有限片段。

管理员人员详情、导出和模型分析均校验 `super_admin`；部门管理员也被拒绝。导出使用只读、可重复读事务与游标分批流式输出，完整结束标记确认记录总数，断连不继续取后续批次。访问、导出、分析写入现有审计，但审计不复制提示词或密钥。

分析预览有效 15 分钟，成功消费后不可再次调用；这是确认授权期限，不是数据删除时间。本次不自动删除历史事件、聊天提交或分析结果，也不新增定时清理机制。企业运维应按公司留存与访问制度管理数据库、备份和获准导出的文件。

## 更新和备份

`021_chat_provider_protocols.sql` 扩展 `providers.protocol` 的检查约束，允许 `openai-chat` 和 `anthropic`，保留原有协议值。现有 `openai` 继续用于 Responses／图片接口；新增选项分别用于 Chat Completions 和 Messages。正式环境需先应用该迁移，才能保存这两种新协议的 Provider。

升级时由现有迁移入口按顺序应用 SQL，不在生产数据库中试删表解决启动错误。数据库备份还需搭配对象存储文件与 Provider 加密密钥；仅复制数据库不能恢复所有成果文件。部署步骤见仓库 `docs/manual/production-deployment.md`。
