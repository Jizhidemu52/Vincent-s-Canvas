# Docker 部署

根目录 Compose 会启动 Web、API、Worker、PostgreSQL、Redis、MinIO、初始化器和备份服务。

根目录模板与 Compose 默认 `OA_LOGIN_ENABLED=false`，使用者可直接打开画布；API 与 Worker 的 Compose 设置会覆盖旧 `.env` 中的开启值。免登录试用不代表员工隔离，只能放在受信网络或受控入口后。启用企业 OA 须显式调整两处 Compose 覆盖，并由 IT 联调公司服务器、正式 HTTPS、可信 OA 接口和网络限制；仅修改 `.env` 不会启用。

## 启动

```bash
cp .env.example .env
# 编辑生产密码、加密密钥、对象存储和可信 OA 接口
bun --env-file=.env ops/preflight/production-preflight.ts
docker compose up -d --build
docker compose ps
```

只允许受控 HTTPS 网关访问 Web，公司网络限制同时覆盖网页、API 与媒体。不要把 `3100`、`5432`、`6379`、`9000` 或 `9001` 暴露到公网，也不要让外层 OA/网关日志保存带 token 的 URL 或 Referer。

## 数据归属

| 服务 | 保存内容 |
| --- | --- |
| PostgreSQL | 员工身份、员工画布文档、部门、权限、项目、账本、任务、历史、素材元数据、审计 |
| Redis | Session、登录限流和任务队列 |
| S3/MinIO | 原图、生成结果、视频、音频、文本和数据库备份 |
| Worker | 从队列取任务，解密服务端 Provider 凭据并执行模型调用 |

企业画布与原图确认云端同步后可由本人恢复，浏览器另保留员工缓存；独立聊天与创意草稿仍为员工分区的本地数据，不承诺全部云同步。旧账号和共用数据不自动迁移或公开。

## 健康检查与日志

```bash
curl http://localhost:3000/api/health
docker compose logs --tail=200 api worker postgres redis minio backup
```

Worker 有独立健康检查：消费进程每 15 秒在 PostgreSQL 和 Redis 探测均成功后更新心跳，超过 75 秒未更新、进程不存在或正在退出时检查失败。用 `docker compose ps` 区分 API 健康与 Worker 健康；健康只证明进程和依赖响应，不证明付费模型调用成功。Compose 日志按单文件 20 MiB、最多 5 个轮转，配置在对应容器重新创建后生效。

## 备份恢复

备份容器定期把 PostgreSQL dump 写到对象存储，原图对象也必须保留和备份。恢复前停止 API 和 Worker，再使用 `restore.sh` 恢复指定对象。完整命令、OA 和并发验收见 [生产部署与验收手册](https://github.com/Jizhidemu52/Vincent-s-Canvas/blob/main/docs/manual/production-deployment.md)。
