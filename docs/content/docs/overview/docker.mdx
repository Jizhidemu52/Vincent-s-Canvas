# Docker 部署

根目录 Compose 会启动 Web、API、Worker、PostgreSQL、Redis、MinIO、初始化器和备份服务。

根目录模板与 Compose 默认 `AUTH_ENABLED=true`、`OA_LOGIN_ENABLED=false`，使用独立账号认证；两项均可在 `.env` 显式配置，不再硬编码覆盖 OA。生产环境禁止两种认证同时关闭。Web 默认仅监听 `127.0.0.1:3000`，用户通过前置 HTTPS 域名访问；异机网关需要显式调整 `WEB_BIND_HOST` 并限定防火墙。Windows 单机开发试用另有入口，不等于生产默认值。

## 启动

```bash
test -e .env || cp .env.example .env
# 编辑生产密码、加密密钥、身份模式及独立外部备份配置
bun --env-file=.env ops/preflight/production-preflight.ts
docker compose up -d --build
docker compose ps
```

只允许受控 HTTPS 网关访问 Web，公司网络限制同时覆盖网页、API 与媒体。不要把 `3100`、`5432`、`6379`、`9000` 或 `9001` 暴露到公网，也不要让外层 OA/网关日志保存带 token 的 URL 或 Referer。

## 数据归属

| 服务 | 保存内容 |
| --- | --- |
| PostgreSQL | 员工身份、员工画布文档、部门、权限、项目、账本、任务、历史、素材元数据、审计 |
| Redis | Session、登录限流和任务队列 |
| S3/MinIO | 原图、生成结果、视频、音频和文本；外部独立 S3 保存备份 |
| Worker | 从队列取任务，解密服务端 Provider 凭据并执行模型调用 |

企业画布与原图确认云端同步后可由本人恢复，浏览器另保留员工缓存；独立聊天与创意草稿仍为员工分区的本地数据，不承诺全部云同步。旧账号和共用数据不自动迁移或公开。

## 健康检查与日志

```bash
curl http://localhost:3000/api/health
docker compose logs --tail=200 api worker postgres redis minio backup
```

## 备份恢复

升级前必须配置独立 `BACKUP_S3_ENDPOINT`、bucket、专用凭据和 `BACKUP_AGE_RECIPIENT`。备份使用同一 PostgreSQL 快照导出数据库与引用清单，数据库和清单通过 age 加密；复制并回读验证原图、缩略图和独立设计库原件后才发布完成标志。不宣称跨数据库/S3 原子快照，媒体须在外部 bucket 启用访问控制和静态加密。恢复前停止所有写入方，使用离线私钥和明确快照编号；完整步骤见 [外部备份说明](https://github.com/Jizhidemu52/Vincent-s-Canvas/blob/main/ops/backup/README.md)及 [生产部署手册](https://github.com/Jizhidemu52/Vincent-s-Canvas/blob/main/docs/manual/production-deployment.md)。
