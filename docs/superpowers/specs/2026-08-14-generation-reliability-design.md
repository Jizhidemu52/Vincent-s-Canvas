# 一期：生成可靠性与图生视频确认设计

## 目标

让用户在 Agent 或画布中生成图片、视频时，先看到真实可用的模型和参数；每个任务拥有可追踪的状态与可恢复结果；图片转视频必须由用户明确选择首帧，而不是系统擅自选择。

本期保持 Agent 的对话式结果界面，不把中间流程图暴露给用户，也不引入通用工作流编排器。

## 范围

### 1. 模型预检

- 模型目录只返回已配置且启用的模型。
- 模型声明自己的能力与限制：媒体类型、可选比例、清晰度、时长、图片数量、是否要求首帧或允许多参考图。
- 前端在模型切换后重置不兼容的预设，并只展示该模型支持的选项。
- 提交前后端都执行预检。前端用于即时反馈；后端是最终门禁。
- 预检失败不得提交上游付费请求，错误信息应说明模型、缺失条件和修复方法。

### 2. 统一生成任务记录

- 每一次图片、视频生成创建稳定的 `requestId` 与任务记录。
- 任务阶段固定为：`preflight`、`submitted`、`polling`、`downloading`、`succeeded`、`failed`。
- 记录模型、有效预设、关联素材、上游任务 ID、阶段时间、可公开的错误分类和用户可见错误文案；不记录或返回密钥。
- 失败分类至少包括：未配置、参数不兼容、额度/权限、上游拒绝、轮询失败、下载失败、网络失败。
- 已提交的任务只能“查询/恢复”，不得在恢复时重放提交请求；显式“重新生成”才创建新 requestId。
- Agent 与画布复用同一任务接口和状态，不维护两套生成语义。

### 3. 图生视频确认卡

- 当 Agent 一次生成多张图片，并且用户表达了生成视频意图时，先显示候选图片卡而不是立即提交视频。
- 用户选择一张首帧；支持在模型允许时附加额外参考图。
- 系统从所选图片、原始需求与当前视频模型生成一份可编辑的视频提示词。
- 卡片展示可用的视频模型，以及该模型对应的时长、比例、清晰度和音频开关；不可用选项不显示。
- 用户点击确认后才创建视频任务。
- 视频成功后，Agent 显示可播放结果；当前画布存在时，将图片和视频结果创建为对应媒体节点并保留来源关系。

## 数据流

1. 前端请求可用模型及其能力描述。
2. 用户选择模型和预设，前端本地验证。
3. 前端调用后端预检；后端验证凭据、模型能力、素材、参数和业务配额。
4. 预检通过后创建任务记录并提交一次上游请求。
5. 任务轮询并下载结果；每一步写入阶段与诊断。
6. 前端轮询或订阅任务状态，只显示用户需要的进度、结果或恢复操作。

## 错误与恢复

- 预检错误：阻止提交，并在控件旁显示纠正操作。
- 已提交任务的临时查询/下载失败：保留 requestId，显示“查询结果”，不显示会重复扣费的重试。
- 上游永久拒绝、余额不足或权限错误：显示明确中文原因，不自动重试。
- 真正重新生成：明确标记为新任务，重新进行预检与扣费确认。

## 非目标

- 不新增通用节点工作流引擎、全画布批量运行或多人协作。
- 不迁移或暴露现有密钥。
- 不保证第三方上游服务可用；系统负责准确呈现其返回和安全恢复。

## 验收与测试

- 未配置、禁用模型不会出现在模型选择中，也不能通过请求直接提交。
- 每个模型只显示其支持的预设；切换模型后不存在旧模型残留的非法参数。
- 图生视频没有选中首帧时不能提交；单图、多图、超出上限分别得到正确行为。
- 每个成功和失败任务均有 requestId、阶段、可理解错误与正确恢复动作。
- “查询结果”不会创建第二个上游提交；显式重新生成会创建新的 requestId。
- Agent 生成结果自动进入当前画布，画布不可用时仍保留 Agent 结果。
