# 画布服务端持久化设计

## 目标

让已登录用户的画布项目可以跨设备自动恢复，同时保留浏览器本地缓存作为离线兜底。第一期不包含多人实时协作。

## 范围

- 服务端保存完整画布快照：节点、连线、聊天会话、当前会话、背景、图片信息开关、视图和更新时间。
- 前端自动拉取、延迟保存、断网本地暂存和恢复后的重试。
- 服务端使用现有项目归属、会话鉴权、资产权限和审计模式。
- 修复本期触及文件中的 UTF-8 中文乱码。
- 为关键保存、恢复、冲突和断网场景补测试。

## 非范围

- 多人实时协作、光标、在线状态或 WebSocket。
- 操作级 CRDT 合并。
- 将图片、视频二进制数据嵌入画布快照。
- 修改现有 WebDAV 手动备份流程；它继续作为显式备份/迁移能力。

## 数据模型

新增画布快照表，与现有项目一对一关联：

- `project_id`：唯一项目关联。
- `owner_id`：用于归属校验和查询。
- `revision`：从 1 起递增的乐观并发版本。
- `snapshot`：JSONB，保存完整 `CanvasProject` 可持久化字段。
- `created_at`、`updated_at`：用于恢复判断和审计。

快照只保存资产的 ID、URL 或 storage key 引用。服务端读取或写入时必须验证这些引用对当前用户可访问，避免跨账号泄露素材。

## API

在现有项目路由下增加受会话保护的接口：

- `GET /api/projects/:id/canvas`：返回服务端快照和 `revision`；没有快照时返回空结果。
- `PUT /api/projects/:id/canvas`：写入完整快照，客户端必须提交最后已知 `revision`。

写入规则：

1. 项目必须对当前用户可见。
2. 新项目可从 `revision=0` 创建第一份快照。
3. 提交 revision 与当前版本一致时，原子更新快照并递增 revision。
4. revision 不一致时返回 `409 CANVAS_CONFLICT`，并带回服务器最新快照和 revision。
5. 成功保存写入审计日志，记录项目、revision 和快照摘要，不写入完整聊天文本。

## 前端数据流

1. Zustand 仍从 `localForage` 快速 hydrate，保证离线可打开旧项目。
2. 已认证用户打开项目后拉取服务端快照。
3. 本地项目不存在或服务端 revision 更新时，使用服务端快照替换本地缓存。
4. 用户编辑画布后，客户端在 1.5 秒空闲后自动保存；离开页面时尽力执行一次保存。
5. 网络或服务端错误时，本地继续保存，并标记“待同步”；下一次可用时自动重试。
6. 收到 409 时，不静默覆盖：保留本地草稿，展示“另一设备有更新”的提示，并允许用户载入服务器版本或以本地版本再次保存。

第一期冲突解决不自动合并节点。这样不会伪造可靠协作结果，也为后续操作级协作保留演进空间。

## 兼容与迁移

- 已存在于 `localForage` 的项目，在用户首次打开时作为首次服务端快照上传。
- 原有 `/api/projects/sync` 继续用于项目元数据，不承担画布内容同步。
- 未登录模式保持纯本地；登录后才启用自动服务端同步。
- WebDAV 同步的导入/导出格式继续可用，不更改其 manifest 版本。

## 错误处理与体验

- 保存中：界面显示低干扰状态，不阻塞画布编辑。
- 已保存：显示最近保存时间。
- 离线：显示“已保存在此设备，等待同步”。
- 冲突：明确显示服务器更新时间和可选动作，绝不静默丢弃本地修改。
- 资产引用失效：保存拒绝并返回具体引用，不写入部分坏快照。

## 验收与测试

### 服务端

- 创建、读取和更新快照。
- 未授权、无项目权限和跨账号访问均被拒绝。
- revision 正常递增，过期 revision 返回 409 且不覆盖数据。
- 不可访问的资产引用被拒绝。

### 前端

- 首次登录会把现有本地项目上传到服务端。
- 第二台浏览器能恢复完整节点、连线、聊天记录、视图与设置。
- 刷新和关闭重开不丢最近编辑。
- 断网编辑可保留本地，网络恢复后自动同步。
- 冲突不会无提示覆盖本地内容。

### 手工验证

以同一账号的两个浏览器配置文件验证：设备 A 创建和编辑，设备 B 恢复；两端分别编辑后验证冲突提示；检查画布引用的图片/视频仍可打开。
