# OpenToken GPT-Image-2 配置设计

## 目标

将图片生成与参考图编辑接入 OpenToken 的 OpenAI 兼容网关，并使用模型 ID `gpt-image-2`。配置完成后，用户可在现有图片工具与画布中选择该模型；图片请求经服务器端发出，密钥不会进入浏览器、代码仓库或文档。

## 方案

复用现有“服务商 / 模型 / 工作流”后台配置能力，不引入新的调用协议或重复的模型实现。

- 服务商：新建或更新 OpenToken，协议选择 `openai`。
- Base URL：`https://cn2.gw.opentoken.io/v1`。
- 凭据：由超级管理员在后台录入 OpenToken API Key；服务器使用现有加密机制保存该凭据。
- 模型：配置并启用 `gpt-image-2`，类型为图片，能力为生成和编辑。
- 调用：使用 `/images/generations`，传递模型、提示词、数量、尺寸、分辨率及可选参考图。

## 行为与限制

- 图片生成和带参考图的编辑均路由至 `gpt-image-2`。
- 沿用项目已有的限制：最多 10 张输出、最多 16 张参考图，支持 1K、2K、4K 分辨率与现有宽高比选项。
- 上游返回非成功状态、无结果图片或超时时，界面显示现有错误反馈，且不会记录为成功任务或重复扣费。

## 验证

1. 后台保存服务商后，公开模型列表中可见且可选 `gpt-image-2`。
2. 普通图片生成请求发往 OpenToken 的 `/v1/images/generations`，请求体模型为 `gpt-image-2`。
3. 参考图编辑请求使用同一模型，并正确携带参考图。
4. 验证空提示词、超过 16 张参考图、上游鉴权失败和任务超时等路径不产生错误的成功记录或额外副作用。

## 安全

不在源码、测试夹具、文档或前端配置中保存 OpenToken 登录密码或 API Key。PDF 内已有控制台登录凭据，运营方应在配置完成前轮换该密码。
