# LLM 对话多格式附件设计

## 目标

LLM 对话页面的附件入口支持图片、PDF、Excel、Word、文本和代码文件。用户发送后，图片作为多模态图片输入；其余可解析文件的文本内容与文件名一并进入对话上下文。

## 支持范围

- 图片：`png`、`jpg`、`jpeg`、`webp`、`gif`，维持现有压缩与图片输入流程。
- 文本与代码：`txt`、`md`、`csv`、`json`、`py`、`js`、`ts`、`tsx`、`jsx`、`html`、`css`、`xml`、`yaml`、`yml`、`sql`、`java`、`c`、`cpp`、`h`、`sh`。
- Office：`xlsx`、`xls`、`docx`。
- 文档：`pdf`。

不支持的二进制文件将被拒绝，并显示准确的支持格式提示。

## 数据流

1. 用户在 LLM 对话的统一附件入口选择最多 5 个文件。
2. 每个文件单独校验 5MB 上限，并校验全部附件 8MB 上限。
3. 浏览器本地解析文件：图片压缩为 JPEG data URL；PDF、Excel、Word、文本/代码提取为文本。
4. 附件列表显示文件名、类型和解析状态。发送时，解析文本以 `[附件：文件名]` 段落附在用户消息中；图片保留为图片内容块。
5. 解析失败不会提交该文件，提示具体原因；已成功解析的其它附件保留。

## 解析规则

- PDF：提取各页可访问文本，按页标记并保留顺序。
- Excel：逐工作表按行导出 TSV 文本，保留工作表名称；跳过空尾行列。
- Word：提取正文段落及表格文本。
- 文本/代码：UTF-8 读取，保留原文。
- 单个附件最多注入 80,000 个字符；超过部分截断，并在内容中标注截断。

## 依赖与实现边界

前端增加仅用于浏览器解析的依赖：PDF.js、SheetJS 和 Mammoth。不会把用户文件上传到第三方解析服务，也不会向模型服务发送原始 Excel、PDF 或 Word 二进制文件。

## 错误与恢复

- 不支持格式：列出可接受格式。
- 文件过大或附件总量超限：不添加该文件，保留当前附件。
- 加密/损坏/没有可提取文本：显示文件名与原因，允许移除或重新选择。
- 文本截断：允许发送，并在对话内容中明确标记为已截断。

## 验收与测试

- 单元测试覆盖格式识别、文本截断、Excel/Word/PDF 解析结果和不支持格式。
- 页面验证上传 `.xlsx`、`.pdf`、`.py`、`.png`，附件均可显示且发送后进入模型输入。
- 验证 5MB 单文件、8MB 总量、空文档、损坏文档和超过 5 个文件的提示。
