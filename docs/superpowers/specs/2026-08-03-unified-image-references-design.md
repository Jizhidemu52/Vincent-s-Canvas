# 统一多参考图设计

## 目标

让设计师在图片生成页和无限画布的图片生成节点中，同时使用本机上传图片、素材库图片和画布图片节点作为有序参考图。提交时按用户看到的顺序传入模型的 `image_urls`。

## 范围

- 图片生成页和画布生成节点使用同一套参考图托盘交互。
- 支持上传、素材库多选、画布图片节点多选，以及已连线图片的自动带入。
- 支持拖拽排序、移除、清空、来源标识、去重和失效提示。
- 保存画布生成节点的参考图顺序，使刷新、导出和再次编辑保持一致。

不新增模型协议、密钥存储方式或独立的参考图管理系统。

## 模型约束

交互一致，但每个模型的限制必须真实反映：

- GPT-Image-2：最多 16 张。
- Gemini 3.1 Flash 图片：最多 14 张。
- Midjourney Blend：必须为 2 至 4 张。
- 普通 Midjourney：不接受参考图。

切换模型时保留现有选择；超出限制的条目会标记，生成操作禁用，直到用户调整到合法范围。

## 用户交互

参考图托盘是一个单一、有序的图片列表。每项显示缩略图、来源标签和图片编号；编号随排序实时更新。

可用入口始终为：上传图片、从素材库选择、从画布选择。画布选择器只展示有可用图片内容的节点并支持多选。连线进入生成节点的图片自动加入托盘；用户移除它只会影响本次生成，不会删除画布连线。

同一张图不会重复加入。文件不存在、无法读取、格式不支持或超出模型限制时，在对应条目或托盘中给出明确原因。

## 数据与提交

新增的统一参考图条目保留来源、稳定标识、预览和可提交的图片数据。提交前执行以下步骤：

1. 合并所有来源并按托盘顺序去重。
2. 验证所有图片仍可读取，并检查所选模型的参考图规则。
3. 依照排序形成 `ReferenceImage[]`，交给现有任务上传与 `image_urls` 管线。
4. 把已解析的顺序写入生成日志和画布节点元数据。

服务端继续执行模型限制，作为绕过前端时的最后一道校验。

## 验证

- 多来源图片混排、拖拽排序与提交顺序一致。
- 重复图片只保留一次。
- 模型切换、上限边界、Midjourney Blend 下限与普通 Midjourney 禁用参考图正确反馈。
- 编辑类任务缺少参考图时保持不可提交。
- 画布节点刷新、导出与再次编辑后参考图顺序不变。
- 失效节点和不可读素材在提交前阻止生成并说明原因。

自动测试使用本机演示服务验证请求的参考图数量与顺序，不提交真实生成请求，避免产生 API 费用。
