# 公司 OA 画布接入

## 已确认的目标

使用者先进入企业微信中的公司 OA，再点击画布。平台复用 OA 的员工身份，不新增扫码或账号密码步骤。企业模式的画布、原图及生成记录按员工隔离，画布保存至服务器。只允许公司网络访问；目标服务器位置和公司出口 IP 尚未提供，由公司 IT 配置，不修改当前网络。

## 接入设计

- 企业模式显式配置 `OA_LOGIN_ENABLED=true`。后端验证现有 OA 入口提供的 `token`，只信任配置的 OA 身份接口返回值。失败时不回退访客身份。前端消费后立即移除地址中的 token，不写入本地存储。
- 企业模式先完成 OA 会话验证，再加载员工分区的创作数据。使用现有 `canvas_documents`、媒体接口和云端同步，不另建存储系统。OA 未认证或会话失效时显示返回公司 OA 的提示，不展示扫码页。
- 画布和媒体的服务端权限以会话里的员工 ID 为准；浏览器请求中的 ID 不是授权依据。本机共享草稿和历史其他员工数据不自动合并到当前员工。
- 保留当前本机免登录试用作为单独模式。它不是企业隔离环境，不能作为公司正式入口。现有试用服务不在尚未完成 OA 联调时强行切换。
- 公司网络限制由可信网关/防火墙覆盖网页、API、媒体及直接后端端口。不能只检查 OA 登录时的来源，不能信任客户端伪造的转发头，也不能只隐藏界面。
- 离开公司网络后不得继续访问服务器；已下载、截图或渲染在设备上的内容不能远程收回。本地恢复缓存不是数据防泄漏方案。

## 实现与验证计划

- [x] 后端恢复配置控制的 OA 交换和企业会话要求；扫码入口继续关闭，管理凭据继续受保护。已验证缺失/失效凭证拒绝、A/B 员工隔离、错误 token 不沿用旧员工身份、文件越权拒绝。
- [x] 前端按部署配置执行 OA 启动和会话验证，启用既有员工云端画布/原图同步，恢复准确的保存状态；已验证不出现扫码页、不加载其他员工本地缓存、不将同步失败显示为成功。
- [x] 更新企业部署说明和配置示例，明确本机试用与正式 OA 模式。公司 IT 提供正式入口、可信 OA 对接和网络允许范围后才启用正式入口。
- [x] 构建并做隔离环境浏览器验证：员工 A 保存文字和图片，完整关闭浏览器、重启测试服务并清空浏览器存储后仍能恢复；原图字节校验一致。员工 B 看不到 A 的画布/媒体，跨标签身份变化清空旧页面，无凭证或错误凭证入口被拒绝。测试仅模拟受信任 OA 身份接口，不调用付费模型；这不代表真实 OA、正式 PostgreSQL/S3 或公司网络已验收。

## 公司 IT 联调输入与验收

1. 确认 OA 的画布菜单指向正式 HTTPS 域名，携带后端可验证的临时凭证；不在聊天、日志、Git 或截图中粘贴真实 token。
2. 确认服务器可访问受信任的 OA 身份接口，证书有效；部署时保持严格 TLS 校验。
3. 确认公司出口 IP 或内网网段，配置网关白名单与后端端口封锁；不能把应用的“可信 IP”配置误当成员访问来源限制。
4. 使用两位真实员工从 OA 分别进入，确认本人数据恢复和相互隔离；从公司外网络验证网页、API、图片入口均不能访问。
5. 服务器数据库和原图存储一起持久化、备份。仅备份前端文件或数据库不等于备份全部照片。
