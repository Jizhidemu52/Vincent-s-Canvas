# 提示词优化：交付与实测记录

本版本把设计师输入、服务端配方优化、严格校验和图片任务连接起来，覆盖 PostgreSQL 正式服务及 SQLite 演示服务。上线版本与提交以 GitHub release 的部署记录为准；本文件记录提交内已经完成的实现与测试，不预先宣称目标服务器验收通过。

## 发布边界

按用户后续明确授权，两份原始文档、完整规则、导入工具、实现源码和本轮合成 QA 证据全部公开。原文标题中的“机密”保留，但它们现在属于公开仓库内容，不再对仓库读者保密。Provider Key、会话 Cookie、`.env`、运行数据库、数据库备份及员工私有项目不公开。设计师 API、前端资源、缓存、画布 ZIP 和普通日志仍不下发服务端规则；超级管理员可管理版本与诊断。供应商执行优化时会收到规则。

## 已实现

- 18 个服务端配方、不可变版本、独立模型绑定、启停、启用/回滚、编译记录、按员工隔离的内容缓存与并发合并；显式导入按哈希去重，不覆盖管理员已有选择。
- 九个创意场景强制优化；系列按分支、工作流按实际上一步结果逐步优化；九个模板节点保持三组并列分支，不改成全串行。
- 图像页、画布配置、快生默认原样发送，可手动一键优化并回填中文，再编辑或生成；显示内容与执行内容一致。批量开关默认关闭，启用后同批只编译一次，首图仅作样图。
- 对话改图、画布助手及反推的规则移至服务端；私有规则参与的聊天先完成校验再展示/执行。失败不自动换模型、不自动重发未知提交、不静默生图；刷新与恢复沿用原请求号。
- 超管“扩写配方”支持版本编辑/对比、模型设置、试优化、试生图与效果对比、用量统计。实际费用、估算与未知分别展示。任务历史只公开最终提示词和允许字段。

实现入口及使用说明见 [本地开发](../../content/docs/backend/local-development.mdx)、[数据库](../../content/docs/backend/backend-database.mdx)、[功能说明](../../content/docs/overview/features.mdx)。

## 文字模型选择

选择已配置的 GPT-6 Astra 作为独立扩写默认，不改变原统一聊天模型。初轮两模型各 6 个同样本：Claude Sonnet 5.5 出现麻灰/麻花语义混淆和纽扣保留色约束不完整；GPT 的图像职责与约束表达相对清楚。随后每模型 3 张真实图多数持平，GPT 的 INCHOICE 字样稍清楚；此小样不证明全面或统计优势。

主矩阵中 GPT 五次漏 `keep_text`，严格校验阻断，没有创建图片。导入器追加“空数组也必须输出”的技术契约后，两模型对这五个原输入复测，共 10/10 格式通过，不重复生图、不覆盖初次失败。复测 GPT 有一次约 80.5 秒，不宣称延迟稳定。详见 [文字与实图对照、严格蒙版](./auxiliary-visual-review.md)。

## 实测范围与主要结果

| 范围 | 已执行与结论 |
| --- | --- |
| 九创意场景 | 各 10 组旧/新输入对照；176 张成功图逐张审阅，3 次编译失败及 1 次未知提交保留，不能称 180 张均成功 |
| 延长对照 | 线稿与服装配色各新增 10 组，累计各 20 组；延长轮 40 张成功，使用追加输出契约的 v2，原 v1 不重试 |
| 线稿延长轮 | 旧版胜 6、持平 4；新版仍有额外纽扣、领扣缺失及细节推断，明确不能称优化更好 |
| 配色延长轮 | 新版胜 5、持平 5；部分门襟/肩部/领部边界更准，但仍不保证实物色差或像素不变 |
| 后五场景 | 排除两个 72px 低清压力样本后的 48 组：新版胜 6、旧版胜 11、持平 30、未知 1；22 张要求透明的结果实际 alpha 全不透明 |
| 其他入口 | 六类工作流各两例、九模板节点各两例、系列两例、反推两例、手写开关与批次样本；另外真实 UI 验证连续对话改图、助手、优化回填、恢复、ZIP、两步工作流与模板拓扑 |
| 其他图片模型 | APIMart 的适用已启用图片通道已覆盖；Nano2.1/Nano2/Blend 的原 QA 参数失败和纠正后独立结果同时保留。OpenToken 四模型余额不足未通过，不充值、不借其他渠道结果代替 |
| 严格蒙版 | 基础/优化两次原始返回均大量改动保护区；现有无损合成后的两张主图保护区变化像素均为 0。证明合成保护，不是模型原生遵循 |

“相对胜出”不等于合格；“成功”仅指协议/结果可取回。图像细节、透明度、辅料结构、指定数量、未确认衣长和编辑范围的失败均列入报告。未做真实面料检测、生产纸样、针迹、印花接缝或实物色差验收；有限重复素材不代表所有业务。

## 调用与费用

统计按范围保留，避免把 HTTP POST、缓存复用、已创建任务、返回图片文件和供应商计费混成同一数字：

- 主矩阵 `visual-v1`：233 条记录，220 success、12 failed、1 uncertain；136 次编译 POST、222 次任务/批次 POST、4 次聊天 POST，216 张图片文件。
- 参数纠正 `protocol-v2`：3 次图片提交，全部成功；2 次编译，Blend 不接受提示词所以不编译。
- 延长矩阵 `visual-v2-extended`：20 次编译、40 次图片提交，全部取回。
- 独立补充：两模型实图对照 6 次、蒙版 2 次，共 8 次图片任务；原始蒙版返回与合成分别保留，所以文件数不等于生成次数。
- 界面额外测试：图像页和快生各一次；对话/助手四次；工作流两步另列于 UI 报告，不混入矩阵。
- 两模型初轮 12 次优化与契约复测 10 次，以及矩阵/UI 的逐条编译记录见 [call-accounting.json](./testing/call-accounting.json)。每条包含版本号、内容哈希、缓存来源、耗时及已返回 token；导出时间即统计截点。

供应商没有返回可核对的真实费用，实际图像/聊天费用均为未知 `null`，并非 0 元；站内扣费配置或估算不是供应商账单。一次 `pattern-craft-03-new` 的提交断线且没有确认任务编号，未自动重发；其真实执行/计费需供应商侧核对。下载失败按原任务恢复，不再次生成。

## 自动化与交付证据

- 服务端全套：1483 pass、31 skip、0 fail，11623 断言；跳过项是未连接原生 PostgreSQL/Redis 的集成条件，不把 PGlite 当真实多进程环境。
- 前端全套：3135 pass、0 fail、29651 断言，包含助手原任务恢复的两个真实组件回归。相关类型检查通过。
- 付费 QA 脚本类型检查、编译器/矩阵/绑定针对性检查通过；发布脚本 7 项、58 断言通过，含中文归档原字节往返、Docker 模板环境文件保留、重复导入保持管理员配置、余额/旧字段改变时拒绝切换。
- 真实 UI 的调用计数、原图 SHA、缓存与 ZIP 检查见 `testing/*report*`；全部公开文件的大小和 SHA-256 见 [evidence-manifest.json](./testing/evidence-manifest.json)。浏览器/系统权限、真实双员工跨设备与高并发仍按 [待验收](../../content/docs/progress/pending-test.mdx) 保留。

上线实操发现正式 `POST /api/tasks` 的受理摘要不含 `resultUrls`，而 SQLite 演示响应带空数组，导致管理员试生图面板报错；原任务仍成功。v0.5.3 在 API 边界补齐待产出字段，新增真实响应形状与原请求 GET 恢复回归。补丁针对性检查 9 项、57 断言通过，Web 类型检查通过；原全套结果为补丁前的有效基线，不将其伪称为补丁后重新执行的全套。发布包另从补丁提交重新构建，线上复验结果保存在对应 GitHub release。

随后正式图像页恢复原草稿时，后端的规范工具 key `image` 与页面别名 `image-generation` 被误判不相同。原用户输入、最终提示词和原图均已正确保存；v0.5.4 复用工具目录规范化后比较，不放松跨工具限制。新增两个别名成功恢复和一个跨工具拒绝的真实页面回归；合并管理员、历史与隔离检查共 50 项、304 断言通过，Web 类型检查通过。线上复验使用已存在原任务，不为恢复再次付费生成。

原图、输入、最终提示词、错误与逐图审阅分别位于 `testing/quality-matrix/`、`testing/visual-review-*.{json,md}`、`testing/chat-live-ui/`、`testing/workflow-live-ui/` 和 `testing/supplement-v1/`。运行数据库不在仓库。发布流程见 [部署脚本](../../../scripts/deploy-prompt-release/README.md)，付费重现入口见 [QA 脚本说明](../../../server/scripts/README.prompt-quality.md)；CI 不会自动运行付费脚本。
