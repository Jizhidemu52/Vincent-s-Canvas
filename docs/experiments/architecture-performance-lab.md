# 画布架构实验：按项目持久化 A/B

## 验证范围

实验分支：`experiment/architecture-performance-lab`。基线提交：`87b282704c733fb1be9a2118baf8d1d92107a854`。本报告记录独立 worktree 当时的对照结果；随后已将验证过的按项目保存逻辑整合进主线，未扩展为整套重构。原始计时文件不因主线整合而改写，不代表新的线上测量。

这不是整套架构重写的验证。现有版本已经有空间索引、可见节点缓存、rAF 拖动预览、Canvas 连线、LOD、结构共享历史和延迟保存，不能把这些算作此次收益。

此次只实现一个独立切口：从“每次保存解析和序列化整个项目列表”，改为“有序项目索引 + 每项目一份无损 JSON”。一次事务只读取被修改项目及相关冲突副本，原子更新文档与索引。公共 Zustand 接口、400ms 保存等待、现有三方合并、失败重试、画布 UI、媒体处理与模型调用路径不变。非 IndexedDB 环境仍走原来的加锁整库存储逻辑。

分片格式使用独立 `:project-documents:v1` 键，不覆盖基线数据，也不自动迁移。主线采用同一约束：更新前在旧版导出需要保留的画布，更新后明确导入；不能将其理解为已有本地项目的无缝升级。

## 测试方法

- 同一 Windows 主机、Chrome、依赖锁文件；两版 production bundle 和完整 Vite production UI。
- 测试浏览器使用全新 context，全部网络拦截，API 为离线桩；不访问用户浏览器数据，不调用收费模型。
- 1 / 10 / 30 个项目，每项目 500 / 2000 节点，含文本、图片引用、连线和聊天。每个输入数据集及 bundle 有 SHA-256。
- 每版每配置预热后 4 次，按 ABBA / BAAB 交替。记录动作到事务完成的耗时、JSON 写入字节、原始 rAF 帧间隔及 Long Task，不过滤 750ms 以上停顿。
- 显式 flush 测保存本身；另测含原有 400ms 等待的自然自动保存。耗时不是 GPU 帧率，也不等于完整画布所有交互性能。
- 刷新读取每版每配置 3 次，属于新页面、暖磁盘缓存，不是冷机启动。两个版本都仍会读取所有项目，未实现按需加载。
- 构建、UI 检查与性能计时分开运行；曾被其他测试污染的初轮数据已弃用。

## 测量结果

结论：**按项目持久化明显改善多项目保存成本，且本轮质量门槛通过；单项目没有一致收益，不能认定整套新架构全面更优。** 建议保留现有渲染架构，把这一独立切口作为增量优化候选，不据此整套重写。

环境：Intel Core i7-14700KF、28 逻辑处理器、约 32GiB 内存，Chrome `152.0.7977.76`、Node `v25.2.1`。共 112 个计时样本、36 个刷新读取样本。以下均为中位数，单位 ms；箭头左为基线，右为实验版。

| 项目数 × 每项目节点 | 单节点内容修改 + flush | 视口修改 + flush | 刷新数据读取（暖缓存） |
|---|---:|---:|---:|
| 1 × 500 | 7.50 → 5.55 | 5.35 → 7.20 | 8.40 → 10.30 |
| 10 × 500 | 34.05 → 5.40 | 33.15 → 5.80 | 24.70 → 20.90 |
| 30 × 500 | 113.85 → 5.75 | 109.45 → 5.15 | 57.90 → 51.30 |
| 1 × 2000 | 28.35 → 22.80 | 16.75 → 18.20 | 14.40 → 20.10 |
| 10 × 2000 | 190.30 → 19.60 | 174.75 → 17.80 | 74.80 → 76.00 |
| 30 × 2000 | 619.75 → 27.30 | 668.30 → 26.95 | 234.40 → 210.30 |

30 × 2000 的单节点保存耗时降低 **95.6%**，4 次范围从 `603.9–643.0ms` 降至 `25.8–28.7ms`，不是仅挑选一次最快结果。每次 JSON 文档写入量从 `50,184,618` 降至 `1,660,636` 字节（约 -96.7%）。这里只计 JSON 字符串的 UTF-8 字节；实验版另外写一个小型结构化索引，不等于物理磁盘总写入量。

自然自动保存保留原有 400ms debounce，计时从 store 修改到真实 IDB 事务完成，不用轮询读库干扰：

| 规模 | 基线 | 实验版 | 判断 |
|---|---:|---:|---|
| 1 × 2000 | 449.40 | 449.75 | 基本无收益 |
| 30 × 2000 | 1032.60 | 444.20 | 降低 57.0% |

这些自动保存数字不包含 React 画布页在调用 store 之前的保存队列等待，不能直接标成“鼠标松开到全部落盘”的耗时。

30 × 2000 的视口保存采样中，原始最大帧间隔 `533.8 → 16.8ms`；自然自动保存 `550.5 → 17.0ms`。**并非所有实验版样本都没有长帧**：该规模单节点 flush 的最大帧间隔为 `66.7ms`（基线 `483.6ms`）。这是存储测试页的主线程可用性证据，不是完整画布 FPS 结论。

代价和不确定性：单项目视口保存慢约 `1.5–1.9ms`；单项目 × 2000 的刷新读取慢 `5.7ms`。单项目节点修改样本的两版区间重叠，不应宣传稳定加速。每版只有 4 次计时，环境仅一台机器；大规模数量级收益可信度高于小幅百分比变化。

完整原始样本、输入哈希、两版 bundle 哈希和每次区间见 [browser-results.json](architecture-performance-lab/browser-results.json)。独立安全检查见 [browser-quality.json](architecture-performance-lab/browser-quality.json)，完整 UI 结果见 [ui-results.json](architecture-performance-lab/ui-results.json)。

## 质量门槛

真实浏览器检查：项目完整字段往返、双标签独立编辑合并、同字段冲突完整备份、多项目事务中途注入配额错误的整体回滚与最新内容重试、删除后刷新不复活、显式清空文档和索引、缺失文档/损坏索引拒绝覆盖原数据。

针对性验证通过：40 项单元/存储集成测试（155 个断言）、16 项真实浏览器安全检查、两版 production 构建、TypeScript 检查。数据安全检查另验证删除后无孤儿文档键、清空后无残留项目索引。

主线整合后再次通过同一组 40 项测试、16 项浏览器安全检查和正式 `bun run build`（含类型检查、画布包体预算）。真实 UI 回归直接加载主线 `web/dist`，拖动、撤销重做、刷新、图像字节与截图均通过；保存模块编译结果 SHA-256 仍与上述实验版一致，因而没有重跑或冒充新的性能数据。主线验证证据见 [integration-quality.json](architecture-performance-lab/integration-quality.json) 和 [integration-ui.json](architecture-performance-lab/integration-ui.json)。

完整 production UI 使用正常项目路由（不是会跳过保存的 `?perf=1` 夹具），10 个项目 × 500 节点，验证拖动 80/40、撤销、重做、刷新；500 节点、499 连线与聊天内容保留。原图为 640×320 带透明度 PNG，恢复后实际图像文件字节及静止图片节点截图两版一致：

- 原始 PNG SHA-256：`2f0149689752ed2fc0609d9850330111e585027e899d456185ac162b452636d1`
- 节点截图 SHA-256：`abda5a5843cfa081df2c952952be9e353287a08f26eb384026eccc8a522ff97d`

这证明本次测试内容与交互没有因存储优化退化，不代表所有媒体格式、所有设备和 AI 生成审美质量都已验证。服务端项目权威状态、多人协作、资产/版本/摆放全面拆分、统一任务重构都未在本轮实现或量化。

## 复现

在本实验 worktree 的 `web/` 下执行，需 Bun、Node、Chrome 和可用 Playwright 模块：

```powershell
bun install --frozen-lockfile
bun scripts/build-architecture-lab.ts --ui
# 若 Playwright 不在当前 node_modules，指定其实际安装目录：
$env:PLAYWRIGHT_MODULE = 'C:/Users/Administrator/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/node_modules/playwright'
node scripts/architecture-lab-ui.cjs
node scripts/architecture-lab-browser.cjs
```

构建脚本从固定 Git 提交读取基线 store，在内存/独立临时源文件中替换；不会切换或覆盖当前源码。它会拒绝其他应用源码、依赖或配置变化，防止把无关改动计为收益。输出到 `output/architecture-lab/`，仅清理本次创建的临时源目录。

计时时关闭其他高负载程序；不要同时运行 UI 检查、构建或另一个基准。`--quality-only` 可单独检查数据安全；`--quick` 仅用于调试，不替代完整对照。
