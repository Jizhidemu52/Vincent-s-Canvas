# 无线画布：本地与局域网部署说明

这份说明适用于 Windows 本机试用和受控的公司 OA 试点。默认试用可直接进入；企业模式从“企业微信 → 公司 OA → 画布”进入并校验员工身份，不新增扫码或密码步骤。运行电脑代为调用已配置的模型额度，使用者无需配置 Key。正式服务器、HTTPS 与公司网络白名单由 IT 落实，详见 [公司 OA 接入](docs/manual/oa-workspace-integration.md)。

> 不要把 API Key 发到群里、写进 GitHub，或粘贴到前端配置。Key 只保存在运行电脑的 `server/.env`。

## 1. 准备条件

- Windows 10 或 Windows 11
- 已安装 [Bun](https://bun.sh/)，在 PowerShell 运行 `bun --version` 能显示版本号
- 已安装兼容的 Node.js，供模型 HTTPS 传输使用；具体版本要求见 [本地开发](docs/content/docs/backend/local-development.mdx#模型-https-运行要求)
- 已从 GitHub 下载或克隆本项目
- 运行电脑可以访问模型服务商网络
- 默认本机试用不需要 OA；企业试点需公司 OA 入口和可信员工身份接口，不使用画布额外扫码登录

## 2. 第一次安装

在项目根目录打开 PowerShell，依次执行：

```powershell
cd web
bun install
cd ..\server
bun install
cd ..
.\Build-LAN.ps1
```

完成后，浏览器页面所需的生产文件会生成在 `web/dist`。

后续也可双击 `Build-LAN.bat`，它构建完整前端；包含后台代码不代表 Windows 单机服务开放管理员登录权限。`Start-LAN.bat` 检查版本标记与实际部署模式，不把旧构建或模式不一致报告为就绪。这是本地测试服务，不等同于 PostgreSQL 生产部署。

## 3. 配置 OpenToken（只在运行电脑做一次）

1. 进入 `server` 文件夹。
2. 若没有 `server/.env`，复制 `server/.env.example` 并重命名为 `.env`。
3. 在 `server/.env` 最后加入以下两行，再填入自己的真实 Key：

```ini
OPENTOKEN_BASE_URL=https://cn2.gw.opentoken.io/v1
OPENTOKEN_API_KEY=在这里填入真实 OpenToken Key
```

4. 保存文件。不要把这个 `.env` 文件上传、压缩发送或提交到 Git。

配置成功后，设计师图片模型列表显示已启用的“出图模型1、2…”；真实名称仅管理员可见。没有配置 Key 的模型不会显示，编号不会因启停重新排列。

## 4. 启动并在本机使用

双击项目根目录的 `Start-LAN.bat`。

首次启动时，若脚本提示不能创建防火墙规则，请先确认使用的是受信局域网，再以管理员身份运行。不要为方便试用向任意网络放行；正式公司允许网段、出口 IP 和代理规则交 IT 配置，脚本的本地子网限制不等于正式白名单已验收。

脚本会显示类似下面的地址：

脚本优先选择已连接的实体以太网或 Wi-Fi 网卡，排除 VPN/WSL 虚拟网卡；防火墙放行限定到选中网卡、本机局域网地址及本地子网。启动后通过健康检查才显示就绪，重复启动复用现有实例。运行日志保存在 `server/.data/lan-server.out.log` 和 `server/.data/lan-server.err.log`。

```text
LAN trial is ready: http://192.168.1.115:5188/
```

默认试用直接打开显示的地址即可进入创作，不需要登录、扫码或员工 Token；这不是企业隔离入口。

公司 OA 试点由维护人员确认接口与入口配置后，在 PowerShell 使用 `.\Start-LAN.ps1 -CompanyOa`。这对应 `OA_LOGIN_ENABLED=true`，使用者从公司 OA 菜单进入，不能仅把试用裸地址当成正式入口。脚本不会把正在运行的试用服务自动切换或重启；切换前先确认运行模式并安排维护窗口。当前试用服务不因准备企业接入而停止。

## 5. 让同一局域网的同事使用

将脚本显示的地址发给同一受信局域网的使用者，例如：

```text
http://192.168.1.115:5188/
```

使用者必须满足以下条件：

- 与运行电脑连接到同一个公司/家庭局域网；
- 使用脚本实际显示的地址，不要使用旧地址或 `127.0.0.1`；
- 运行电脑保持开机，且服务没有停止。

默认试用保持 `OA_LOGIN_ENABLED=false`，不显示身份、积分和角色入口；企业模式设为 `true`，必须验证 OA 员工身份后才加载创作数据。两种模式都不提供额外扫码或内部积分流程，旧 `AUTH_ENABLED` 等字段不能代替 OA 模式选择。

试用沿用共用创作身份保存生成素材和任务，不保证员工隔离。企业模式按已验证员工保存画布、原图、素材与任务；所有调用仍使用运行电脑的模型额度，免内部积分不代表外部 API 免费。旧共用草稿和其他员工数据不自动迁入当前员工，也不向访客公开。

局域网 `http://` 地址仅用于受信试用，能访问入口的人可能发起付费生成。正式企业入口必须经 HTTPS 和公司网络限制，网页、API、媒体及后端端口都在限制范围；不能仅检查 OA 登录时的 IP。模型凭据始终只保存在服务端。

## 6. 更新到 GitHub 最新版本

在项目根目录执行：

```powershell
git pull --ff-only origin main

cd web
bun install
cd ..\server
bun install
cd ..
.\Build-LAN.ps1
```

前端更新后刷新网页即可。若更新了服务端或 Key，等待生成任务结束，停止旧的本项目服务后，再双击 `Start-LAN.bat`；重复双击只会复用已有服务，不会自动重启。更新前备份 `server/.env`、`server/.data` 和重要画布；拉取遇到本地改动冲突时不要强制覆盖。

## 常见问题

### 其他电脑打不开网页

确认两台电脑在同一局域网；使用启动窗口打印的地址；检查运行电脑没有休眠；必要时以管理员身份重新运行 `Start-LAN.bat` 以创建防火墙规则。

### 网页能打开，但生成图片失败

检查 `server/.env` 是否存在 `OPENTOKEN_API_KEY`，Key 是否有效、是否有额度；保存后重新启动 `Start-LAN.bat`。模型下拉框只会显示已经配置成功的服务。

### 其他同事能打开但等待很久

图片/视频耗时主要由上游模型生成决定。先在运行电脑本机生成一张同样规格的测试图：若本机也慢，属于模型服务耗时或额度/排队问题；若本机快而其他电脑慢，检查运行电脑网络、Wi-Fi 信号和局域网稳定性。

### 需要正式公司入口

本项目当前目标只允许公司网络访问，不为外网人员开放。公司 IT 需确认服务器位置、公司出口 IP/网段、正式 HTTPS 域名和 OA 菜单凭证对接，再落实网关白名单与后端端口封锁。上述参数及真实联调尚未完成，不能以局域网试用代替正式交付；已下载或缓存的图片无法靠网络限制远程收回。

## 安全提醒

- 所有使用者共享运行电脑配置的模型额度。
- 不要上传涉及客户机密、个人隐私或未经授权的图片资料。
- 素材和任务保存在 `server/.data/local-demo.sqlite`；企业模式还保存员工身份与云端画布原图，本地保留员工缓存。独立聊天和创意草稿仍是浏览器员工分区数据，试用画布只在浏览器保存。企业画布离开前确认已同步；本地内容换设备前导出，旧数据不自动迁移或公开。
- 中断任务不会自动重发。企业会话失效后应从 OA 重新进入，不绕过验证；默认试用无需登录。备份时先停服，再复制整个 `server/.data` 目录；不要运行中只复制 `.sqlite` 主文件。正式 PostgreSQL 与原图对象存储必须联合备份。
